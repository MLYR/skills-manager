# AI 解读开发与运行流程

## 1. 开发原则

- 按阶段串行推进；当前阶段未验收，不进入下一阶段。
- 先冻结数据契约和 Tauri Command，再分别实现后端和前端。
- 每次只做当前阶段需要的最小改动，不顺手重构现有大组件。
- 每个阶段必须包含正常路径、失败路径、恢复路径和安全验证。
- 所有新增关键逻辑写“为什么需要它”的注释，不写复述代码的无效注释。
- 不自动执行提交、推送、建分支或创建 PR。

## 2. 阶段流程

### 阶段0：基线与契约

工作内容：

1. 记录工作树、依赖、lint和Rust测试基线。
2. 确认三类 Skill 的身份规则和主文档读取入口。
3. 冻结数据库字段、任务状态机、AI输出Schema和Tauri DTO。
4. 列出需新增/修改的命令和页面。

验收门：契约能覆盖中心、全局本地、项目本地三类 Skill；前后端字段不存在歧义；`03-progress.md` 已记录基线证据。

### 阶段1：数据库和服务配置

工作内容：

1. 新增数据库迁移和新库初始化结构。
2. 实现普通配置读写、Keyring中的API Key增删查状态。
3. 实现Provider预设、Base URL校验和连接测试。
4. 添加日志清理基础能力。

验收门：新库、v7旧库升级、重复迁移均成功；Key不落盘；正确和错误配置均能返回可读结果。

### 阶段2：单个Skill解析闭环

工作内容：

1. 安全读取主文档、计算`source_hash`和预估文本量。
2. 构造防注入提示词并调用AI。
3. 校验JSON Schema，保存结果、Token和日志。
4. 提供预览、解析、查询、重新解析Tauri Commands，并实现可领取已确认Job的最小持久Runner及启动恢复。

验收门：使用本地假服务分别模拟成功、401、429、超时、5xx、非法JSON；结果、错误、日志和重试策略符合方案。

### 阶段3：详情和列表接入

工作内容：

1. 详情页新增默认AI解读标签及所有状态页面。
2. 结构化展示八类字段、免责声明、复制示例和重新解析。
3. 列表接入一句话摘要、过期标记和回退策略。
4. 搜索接入AI摘要和适用场景。

验收门：已解析、未解析、解析中、失败、过期、未配置AI、无主文档均有明确界面，不出现空白或假进度。

### 阶段4：批量任务和持久恢复

工作内容：

1. 批量扫描、成本估算和隐私预览。
2. 在阶段2单任务Runner上扩展批量并发、暂停、继续、取消和批次管理。
3. 退避重试、应用关闭恢复和单项重试。
4. AI管理页统计、筛选和进度展示。

验收门：运行中的批量任务关闭应用后可恢复；暂停时不发新请求；取消项不重试；总进度由持久任务状态计算而非前端计时器模拟。

### 阶段5：日志、安全和收尾

工作内容：

1. 日志列表、详情、复制和一键清空。
2. 启动时清理超过保留期的日志。
3. 检查密钥、认证头、错误信息和导出内容的脱敏。
4. 完成i18n、测试、文档和回归验证。

验收门：人为制造过期日志可被清理；恶意Skill内容不能改变输出协议；仓库内检索不到测试Key和认证值；原有Skill管理功能回归通过。

## 3. 产品运行流程

```text
用户配置AI
  -> 测试连接
  -> 选择单个解析或批量范围
  -> Rust读取主文档并计算哈希
  -> 计算字符/Token/费用预估
  -> 前端展示发送内容预览
  -> 用户确认
  -> 创建持久化任务
  -> Runner从Keyring获取Key
  -> 构造安全提示词并请求模型
  -> 校验结构化结果
  -> 保存解读和日志
  -> 更新任务状态
  -> 前端刷新详情、列表和统计
```

任何失败都必须终止在可恢复状态，并在管理页给出下一步操作。禁止捕获异常后静默回退为“未解析”。

## 4. 单任务处理流程

1. 根据目标身份重新定位Skill，避免使用入队时的过期绝对路径。
2. 通过现有安全路径校验读取主文档。
3. 重新计算`source_hash`；若预览后的内容已经变化，停止并要求重新确认。
4. 读取批次确认时的AI配置快照，并从Keyring获取当前凭据。
5. 生成系统提示、用户提示和Schema版本。
6. 写入“开始请求”日志，不包含认证信息。
7. 发起可取消的HTTP请求。
8. 校验HTTP状态和响应JSON。
9. 校验AI业务字段，限制字段长度和数组数量。
10. 事务性保存解读、Token、日志和任务状态。

## 5. 批量任务流程

1. “一键解析”仅选择未解析的 Skill；待更新（`stale`）内容必须通过详情页或明确的定向预览重新解析。
2. 扫描阶段只读文档，不调用模型。
3. 汇总有效、无文档、不可读和预计用量。
4. 用户确认后一次性创建队列记录。
5. Runner按优先级和创建时间领取任务，保证同一目标同时只有一个活动任务。
6. 暂停只阻止领取新任务；当前请求完成后进入暂停状态。
7. 取消同时标记未开始任务，并尽力中止当前请求。
8. 批次完成后展示成功、失败、取消和跳过数量。

## 6. 失败与重试流程

| 情况 | 自动重试 | 用户提示 |
|---|---:|---|
| 429 | 是 | 服务限流，显示下次重试时间 |
| 超时/临时网络失败 | 是 | 网络异常，正在有限重试 |
| 500/502/503/504 | 是 | 服务暂不可用 |
| 401/403 | 否 | 检查API Key和权限 |
| 400/404 | 否 | 检查Base URL、模型和接口兼容性 |
| 非法JSON/字段缺失或类型错误 | 最多一次纠正 | 模型未返回兼容格式 |
| 文档变化 | 否 | 内容已变化，请重新预览确认 |
| 用户取消 | 否 | 已取消 |

重试次数必须持久化，不能因重启归零。达到上限后进入`failed`；用户手动重试也必须重新预览并确认费用，再创建新批次，不能重置原Job绕过费用上界。

## 7. 每阶段交付步骤

1. 执行者（主会话或委派的子代理）在`03-progress.md`把阶段改为“进行中”。
2. 写明本阶段文件范围、接口变化和最大风险。
3. 完成最小实现和对应测试。
4. 执行贴近改动点的验证，保存实际命令和结果摘要。
5. 做至少一次失败路径反向验证。
6. 自检无关格式变化、注释丢失和敏感信息。
7. 改为“待验收”，由主会话复查；可自审（如实登记），也可使用全新只读子代理独立审查。
8. 验收通过后才改为“已完成”并累计权重。
9. 每阶段验收通过后，先提交该阶段代码与进度文档，再开始下一阶段。

## 8. 发布前回归范围

- 中心库Skill列表、详情、更新和删除。
- Agent全局工作区和项目工作区列表、详情与同步。
- 设置保存、应用重启、系统钥匙串读取。
- 数据库旧版本迁移和首次启动。
- 深浅色主题、中英文、窗口窄宽状态。
- 无网络、未配置AI、错误Key、限流和服务超时。
- 日志到期清理、手动清空和导出日志时的敏感信息检查。
